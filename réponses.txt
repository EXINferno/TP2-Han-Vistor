Question 7.

git merge fusionne une autre branche dans la branche courante,
cela crée un commit de fusion si des modifications ont été faites de part et d'autre,
il conserve l’historique complet des branches parallèles.

Question 8.

git rebase <branche> repositionne les commits de ta branche comme s’ils étaient faits après la branche donnée,
permet de réécrire l’historique de façon linéaire, sans commit de fusion,
utile ici pour faire un squash (= un seul commit propre pour plusieurs petits commits).
